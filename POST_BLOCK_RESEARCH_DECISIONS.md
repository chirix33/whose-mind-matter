# Post-block research decisions and the next development block

Project: Whose Mind Matters? / OfficeMinds / VoMI-Router  
Date: 2026-10-28  
Research-driver ruling, via Ashraf.

## Disposition

**Accept completion of the autonomous block. Do not start bulk labels, learned allocation, or another note-prompt optimization loop. Approve a bounded scenario-and-reference qualification block using the original research factors.**

The block found no stable added value from legally inferred notes on its nine inspected states under the tested API policy. This is a useful negative development result. It is not a general absence-of-value result for explicit mental modeling, nor a test of the planned learned VoMI-Router.

Two issues now take priority: the reference uses some information not disclosed to the actor, and the current scenarios often permit cheap asking or physical search. Correcting those issues is necessary to test the original question, not permission to construct tasks until a preferred method wins.

This ruling is based on the attached `FINAL_REVIEW.md` only. Current r5 rules, source diff, reference audit, per-episode records, exact note payloads, and gate reports were not attached. Previous source inspection does not verify the latest changes. LLM plan gates and arithmetic recomputations are useful checks, but do not establish independent scientific validation. Include the existing compact evidence bundle with the next handoff.

## Decisions on the six requested questions

### 1. r5 and pilot-v2.1

Retain r5 and pilot-v2.1 as **versioned working diagnostic artifacts**, pending fresh-context validation. Do not yet designate either a validated final contract/package.

Acknowledge that pilot-v2.1 was revised on these contexts and that local behavior worsened on some rules. Report results by backbone. Do not infer cross-model robustness from the API improvement. Keep the original package available as a comparator when useful; no further package search is required in this block.

Preserve the five flagged ambiguous contexts in all denominators and report them separately. The other 19 can be described as consistent under the audited model, not automatically consistent with every reasonable reading of the public history. Audit honesty-rate dependencies too: a generator posterior of 1.0 is not logically entailed by visible evidence if it depends on an undisclosed zero-probability alternative.

### 2. What counts as out-of-sample?

All inspected dev-v2 remains development data. A new seed under the same generator provides a **fresh-instance check**; it does not establish unseen-template or unseen-family generalization. Newly designed templates provide a **new-template development check**, with the design still informed by previous findings.

Use a versioned **dev-v3** for the next block. Fix its generator, strata, parameters, seed policy, pairing, exclusions, and scoring before any LLM output. Record which properties are new. Do not call dev-v3 a final untouched test set: once used for development decisions, it is development data.

An eventual confirmatory set will be generated and frozen after the method/protocol is fixed, with held-out structure as appropriate. Previously inspected families cannot become a genuinely unseen family split simply by relabeling them.

### 3. Approve revised state design, with safeguards

Approve F1/F2/F4/F5 scenarios already contemplated by the outline: distractors, depth/path minimal pairs, holder permutations, and stakes. Add delayed/relayed evidence when the relevant informant has departed before decision time. Preserve ordinary asking, physical search, and the original reward coefficients.

The proposed scenarios must satisfy two distinct tests:

1. **Task-level mental relevance:** under the declared public dynamics, changing a person's information/belief perspective can change which task action is useful while the relevant physical situation is held fixed.
2. **Explicit-computation benefit:** the actual bounded LLM may or may not benefit from an additional mental unit derived from its existing history.

The first does not guarantee the second. A direct model can reason implicitly about the same evidence. Do not certify a task as requiring explicit notes or a particular LLM reasoning depth merely because a restricted symbolic policy fails.

Use larger layouts or shorter feasible horizons only as justified instances of the original task scope, with timing and reachability documented. Do not remove a legal solution, raise asking's price, or choose a horizon after observing an LLM's failure. Do not screen scenarios by which method wins.

### 4. Reference semantics: align public information

**The primary reference must condition on information actually available to every compared actor.** If exact posteriors use base rates, honesty rates, or templates, those assumptions must be part of the declared shared public model. They cannot remain hidden and then be used to score an actor's uncertainty as wrong.

Use two clearly separated strata:

- **Evidence-resolved:** mental content follows from visible access/communication evidence and the explicit update rules. Deterministic labels require no undisclosed frequency assumptions.
- **Probabilistic:** unresolved possibilities remain. Supply the relevant prior/rate and response model identically to all arms, fixed before the realized world is sampled. Compute the reference posterior from that shared specification.

Disclosing a prior is not disclosing the realized hidden state. Do not reveal sampled world IDs, actual private beliefs, answer-bearing scenario tags, or roles determined by hidden truth. If a prior/template itself entails a role, record that as public task information and assess whether it trivializes the task.

Keep the old generator-informed reference as a historical diagnostic. Do not retroactively describe it as the posterior available to the old policy. In particular, calling s9 a demonstrated probability-calibration failure is premature: its comparison to P(unmoved)=0.70 uses a base rate the policy was not told. A fresh matched-information risk check is required.

### 5. Ask-aware labels: yes

Include the legal `ask(person, q)` option and its consequences in the reference continuation and realized policy rollouts. Internal inference and external questioning are different actions. A computation's value is conditional on the actual competing options, including asking, moving to ask, waiting, searching, and delivering.

Do not label a unit against a deliberately mind-blind or no-ask actor and then treat that label as exact value for the LLM that can ask. Keep symbolic-reference, realized LLM, and privileged-information quantities distinct.

The statement that an askable informant's unit is worth at most one 0.05 step is not a general theorem. It requires conditions such as immediate access, a truthful complete answer to the same query, no intervening dynamics, and equivalent subsequent decisions. Reliability, nested beliefs, travel, deadlines, and deceptive or incomplete answers can break those conditions. State any restricted bound precisely; otherwise describe the observed pattern in the tested scenarios.

Including asking may make many unit values zero or small. Preserve those cases. STOP and cheap external information are legitimate competitors.

### 6. Doubt/caution

Treat s9 as a presentation-sensitive diagnostic, not demonstrated mental-content value. Expressed doubt may alter policy behavior even when it adds no valid mental-state information. The observed change does not by itself establish either a calibrated method component or an exclusively generic cue mechanism.

If using a general reminder to compare irreversible-error risk with asking/search, place it in the **same policy/task instructions for every arm**, including direct, and freeze it before the new outcomes. Do not add an unsupported numerical doubt value to just one note condition.

Compare numerical risk against the supplied public prior, rewards, and legal alternatives. Keep epistemic uncertainty about a person's belief separate from a generic instruction to be cautious. Do not count a shared policy-calibration repair as evidence for selective mental allocation.

## Next authorized block: qualification first, then a small diagnostic

Choose local or cloud execution within the existing resource permissions. Prefer free/local computation for generator and reference checks. Continue routine engineering work without requesting a preparation-only review.

**Bound this block to two rounds. No new controller training, prompt search, or full API five-arm run.**

### Round A — New development generator and public-model qualification

Prepare a compact generator with **12 base groups** in four prespecified strata, three groups each:

1. physical/STOP controls, including irrelevant people;
2. evidence-resolved first-order mental relevance;
3. evidence-resolved directed depth-2/relay relevance, with at least one departed-informant construction;
4. uncertain reliability/staleness with explicit shared priors and stakes.

For each group produce a declared holder/name permutation and stakes x1/x4 variants, yielding up to 48 instances. If a permutation is intentionally observationally indistinguishable, label it as such; do not claim it changes visible evidence. Assign distractor conditions in balanced blocks in advance rather than taking a full factorial. Sample the group's hidden world only after its public parameters are fixed and share the same exogenous draw across appropriate paired variants.

These are development design strata, not estimates of real-world scenario prevalence. State their fixed proportions and any qualification exclusions. Zero-value cases must not be removed because they fail to create inference headroom.

Before LLM execution:

- validate public rules against transitions over the finite support used by the reference;
- validate belief truth/false-belief semantics, self-location semantics where claimed, and perspective access;
- verify that exact-reference inputs are a subset of the shared public model plus visible history, not actual hidden-instance secrets;
- verify that evidence-resolved labels do not require undisclosed priors or honest-template assumptions;
- enumerate feasible action consequences on tiny instances, with asking enabled;
- construct same-physical-state social-history pairs and show the relevant action-value differences under the declared dynamics;
- quantify physical-search and ask alternatives, including their step costs, delays, errors, and availability; do not merely assert they are inferior;
- check that target facts are inferable in the intended mechanistic cases and not handed to the actor through a role-order/name/metadata cue;
- audit first-person self-location units separately from other-perspective units;
- check prior independence, replay, pairing, prompt rendering, and reference support.

Classify self-location cases rather than silently excluding them. Do not count their privileged true-content benefit as evidence of deployable perspective reasoning. The direct baseline always keeps the full legal history and shared rules.

Limit exhaustive computations to a tractable finite specification. If an optimizer/reference is approximate, record its approximation. Do not claim global optimality or exact minimum depth from a heuristic search. Maintain the existing distinction between structural mental relevance and value for the tested bounded actor.

Freeze dev-v3 and hash its files, public contract, prompts, strata, and model settings before observing new LLM outcomes. Produce a short design manifest and qualification report.

### Round B — Fresh-context value-of-notes sanity check

If Round A passes, execute a modest local diagnostic using the existing validated backbone and frozen package. Do not add a model or tune the package on dev-v3 outcomes during this block.

Use a predeclared hash selection of one group per stratum, with the specified paired variants and no outcome-based replacement. Compare no notes, inferred notes, grounded public-model reference notes, and privileged true-content notes using fixed allocations. Record when a condition is identical or supplies no new content; preserve that result.

Freeze note payloads before policy outcomes. Use three fresh policy continuations per selected state/condition where practical, with complete resets, the same legal asking/search, counterbalanced ordering, and symmetric retention/refresh rules. Fewer draws or a staged subset are acceptable only under a declared resource rule, not because results look unfavorable. Explain that policy draws are nested within groups, not independent new scenarios.

The inference and decision backbone must be reported; do not transfer an API finding to the local model or vice versa. An optional small API sanity batch is permitted only after the qualification checks pass and only if its worst-case reservation fits the **remaining original USD 5 total cap**, including a reserve for failures. The report estimates about USD 1.1311 remains; reconcile the ledger before dispatch. Do not increase the cap or start a paid cloud service beyond that allowance. If the API check cannot fit, finish the free/local diagnostic and report the missing API confirmation.

Report raw return, success/error/steps, unit fidelity under the aligned public model, coverage, note/policy compute, and all per-group results. Include zero-value controls and disagreements. Do not select a new variant after seeing these results.

## Stop and return

Return after these two rounds, or sooner for a genuine scientific/resource blocker. A valid outcome is that direct reasoning still leaves no measurable explicit-note headroom. Do not begin allocation learning automatically even if the diagnostic is positive.

Provide one compact bundle containing:

- the previous block's promised source diff, r5 rules, `reference-audit.json`, Round 1 tables, Round 2/3 episode CSVs, note hashes, and experiment registry;
- the new public-model specification, strata, generator qualification results, freeze manifest, and exact inference/policy prompts;
- representative matched public/privileged traces demonstrating evidence access and ask-aware action values;
- fresh-context outcomes by group and condition, with uncertainty and compute accounting;
- source/prompt/data hashes, tests actually run, deviations, and ledger status;
- a recommendation on whether the next milestone is allocation learning, further inference/integration work, or a reconsideration of empirical headroom within the original goal.

Do not describe new-seed or new-template development performance as a confirmatory result. Do not describe a bounded policy given true content as a guaranteed upper bound. Preserve negative findings and the original paper objective throughout.
